Executive Summary

Three agents. Five gaps. One scoring model that needs a full replacement.

The current four-agent pipeline (Research → Enrichment → Scoring → Personalization) is structurally sound but calibrated to an outdated 6-signal, firmographic-heavy scoring model. The v2 model introduced by LaunchHouse inverts the weight distribution — moving mass from static company attributes toward dynamic operational signals. The majority of required changes are prompt and config only; no schema migrations are needed.

Core Strategic Shift

"Your agent should not ask: 'Who uses Cvent?' It should ask: 'Which Cvent-using event team has a real operating reason to need execution help now?' Cvent usage is a gate, not a signal. Scores should reflect compound evidence of operational pressure."

Critical · Fix Now

Scoring Model — Full Replacement

6-signal prompt must be replaced with the v2 8-signal model including 7 hard caps and a compound-evidence Hot gate.

Critical · Fix Now

4 Research Query Sets Missing

Hiring (ATS-targeted), Cvent complexity, MarTech pressure, and Cvent Certified are not queried at all today.

Critical · Fix Now

Enrichment Output Schema Incomplete

5 structured signal blocks required by v2 are absent from EnrichmentAgent output: hiring signals, complexity, certified profile, capacity stress index, source confidence.

Medium · Phase 4

PersonalizationAgent Routing

No structured routing table exists. recommended_template_driver and 4 hook fields are not written to personalization_hooks.

Hard Acceptance Rules

Implementation is complete only when: (1) all 6 QA scenarios hit expected tier and routing; (2) no lead scores Hot on a single weak signal; (3) Cvent usage alone never produces a Hot lead; (4) every Hot-score lead includes a high-confidence source URL for its primary signal driver; (5) recommended_template_driver is present in message.personalization_hooks for all scored leads.
